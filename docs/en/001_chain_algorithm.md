# Same Chain Detection Algorithm for Previous River

## Purpose

To provide an algorithm for determining whether "Node A and Node B exist on the same path (chain)". This prevents infinite loops of links and structural contradictions from occurring during note insertion operations.

## Terminology

- **Same Path**: A state where one is an ancestor (or descendant) of the other within the unidirectional list of the `previous` property.
- **Siblings**: A state where nodes share a common ancestor but have no direct parent-child relationship. This determination algorithm does not consider them to be on the same path (it returns `false`).

## Design Philosophy

The specifications for correctly determining relationships between nodes and a safe traversal method to prevent circular references have been defined.

| Consideration | Adopted Idea | Rejected Idea | Reason |
|---|---|---|---|
| Basic function | Unidirectional recursive search using `isAncestor` | Simple comparison of `previous` properties | To accurately identify ancestors even when the hierarchy is deep. |
| Function name for bidirectional check | `isOnSamePath` | `isConnected` | Because `isConnected` risks misidentifying sibling relationships as "connected". |
| Function name for bidirectional check | - | `areOnSameChain` | Because the term "chain" leaves ambiguity in the context of data structures. |
| Countermeasure against infinite loops | Recording visit history using a `visited` (Set) | - | To prevent crashes caused by circular references (cycles) unintentionally generated by user operations, etc. |

## Implementation

### Ancestor Check (`isAncestor`)

Determine if `target` is an ancestor of `note`. It traverses the `previous` properties of the nodes sequentially and uses a `visited` set to detect circular references.

```typescript
export function isAncestor(app: App, note: TFile, target: TFile): boolean {
  let current = note;
  const visited = new Set<string>();
  visited.add(current.path);

  let depth = 0;
  const maxDepth = 100000;

  while (depth < maxDepth) {
    const prev = getPreviousNote(app, current);
    if (!prev) {
      return false;
    }

    if (prev.path === target.path) {
      return true;
    }

    if (visited.has(prev.path)) {
      return false; // Circular reference detected
    }

    visited.add(prev.path);
    current = prev;
    depth++;
  }

  return false;
}
```

### Same Path Check (`isOnSamePath`)

Determine if two notes are on the same path. It verifies the ancestor relationship from A to B, or from B to A.

```typescript
export function isOnSamePath(app: App, note1: TFile, note2: TFile): boolean {
  if (note1.path === note2.path) {
    return true;
  }
  return isAncestor(app, note1, note2) || isAncestor(app, note2, note1);
}
```

## Use Cases

It is used as a validation (safety mechanism) to prevent invalid operations in various commands of Previous River.

### Preventing Circular References

During node insertion operations (`Insert note`, `Insert note to first`, `Insert note to last`), if the target node already exists on the same path, the operation is blocked. This prevents the note link structure from falling into an infinite loop.

```typescript
if (isOnSamePath(app, file, selectedNote)) {
    new Notice(`Cannot insert: "${file.basename}" and "${selectedNote.basename}" are on the same path.`);
    return;
}
```
